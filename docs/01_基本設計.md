# 01 基本設計 — TOKI 道場

作成: 2026-09-27／対象: 版 0.1

## 1. 目的

GMOコインの**公開リアルタイム配信**の値で、**仮想の売買**をしてデイトレードを訓練する。
お金は動かない。訓練の成果は「偶然に入った場合と比べてどうか」で測る。

## 2. 利用者と使い方

- 利用者はリポジトリの持ち主1人
- 主な端末はスマートフォン（iOS Safari・Android Chrome の最新版）。PC のブラウザでも使える
- 使う場所は問わない（自宅の PC を付けておく必要は無い）

## 3. 範囲

### 3.1 入れるもの

| 番号 | 機能 |
|---|---|
| F-1 | 銘柄の選択（BTC・ETH・XRP・SOL・DOGE・XLM・ADA・BCH）と、**現物／レバレッジの切り替え**（レバレッジは GMO に銘柄があるものだけ） |
| F-2 | リアルタイムの**最終価格・最良気配・スプレッド**、**板**（売り買い各10段）、**約定の流れ**（直近30件） |
| F-3 | **ローソク足のチャート**（1分・5分・15分・1時間）、移動平均（20・75）の表示の切り替え。**開いた瞬間から1画面ぶん（約120本）の過去の足を出す**（GMO の公開の過去の足を中継で取る。§7）。その先は開いてからの約定で足を伸ばし、端末に7日ぶん貯める |
| F-4 | **注文**: 成行・指値・逆指値。現物は買い／売り（売りは保有の範囲）、レバレッジは新規（買い・売り）と決済。レバレッジの建玉に損切り・利確を付けられる。待機中の注文の取り消し |
| F-5 | **口座**: 仮想の現金・現物の保有・レバレッジの建玉・評価損益・証拠金維持率 |
| F-6 | **振り返り**: 取引の一覧（メモつき）、勝率・平均損益・手数料・最大DD・時間帯別、**偶然との比較**、CSV/JSON の書き出し |
| F-7 | **設定**: 仮想資金の選択（初期3万円）とリセット、通信の遅れ、表示の切り替え |

### 3.2 入れないもの

- 実際の発注・API キー・GMO の非公開 API（どの形でも）
- 過去の日の早送り（リアルタイムだけと決めた）
- サーバー・利用者どうしの共有・複数端末の同期
- 過去の足の中継（Cloudflare Workers）。必要になったら別の版で足す

## 4. 非機能の要件

### N-1 分離: 既存の取引に影響を出さない

| 要件 | 満たし方 |
|---|---|
| N-1a 実口座に触れる経路が無い | API キーを持たない。非公開 API（`/private/`）の文字列をコードに置かない（構造のテストで固定） |
| N-1b TOKI 本体と独立 | 別リポジトリ（公開）。TOKI の `toki/`・ワークフロー・状態ファイルを参照しない |
| N-1c 通信の経路を共有しない | 利用者の端末から GMO の公開配信に直接つなぐ。過去の足だけは Cloudflare の中継を通す（§7。TOKI とは別の場所・別の IP）。TOKI の GitHub Actions とは IP も経路も別。購読の頻度制限（1秒1回）を守り、GMO 側に負担をかけない |
| N-1d 自動で動く仕組みを持たない | GitHub Actions を置かない（Pages は「ブランチから配信」） |

### N-2 安全: 公開しても攻撃されない

守るもの: 利用者の端末とブラウザ、端末に貯めた記録、リポジトリ。秘密は持たない。

| 脅威 | 対策 |
|---|---|
| スクリプトの注入（XSS） | 画面への書き込みは `textContent` と DOM の組み立てだけ（`innerHTML` を使わない）。CSP で自分のスクリプト以外を実行させない |
| 第三者のスクリプトのすり替え | チャートの部品はリポジトリに同梱し、SRI（ハッシュ）を付けて読む。外部の CDN を使わない |
| 受け取るデータの細工・巨大化 | 電文は JSON として検査し、数値は有限・正、配列は長さの上限、電文の大きさの上限。外れたものは捨てる |
| よそのページへの埋め込み（クリックの乗っ取り） | Pages はヘッダーを付けられないので、埋め込まれていたら描画をやめる |
| 書き出したファイル経由の攻撃（CSV の数式） | `= + - @` で始まるセルは先頭に `'` を付ける |
| 端末の容量を食い尽くす | 保存量に上限を設け、古いものから消す |
| 公開物からの情報漏れ | コミットの作者は `Claude <noreply@anthropic.com>`。TOKI の戦略・状態・個人情報を入れない |
| 同じ `github.io` の他のサイトとの混線 | 端末の保存は固有の名前（`toki-dojo-v1`）で分ける。秘密は保存しない |

### N-3 本物らしさ: 実際の使用になるべく近づける

- 銘柄の仕様（最小数量・数量の刻み・値段の刻み・Taker/Maker の手数料）は **GMO の `/v1/symbols` の実値**（2026-09-27 取得）を使う
- 成行は**今の板を食う**（数量ぶんの加重平均）。板が足りなければ残りは約定させない
- 指値は**値段が突き抜けたときだけ**約定（触っただけでは約定しない）
- 手数料は**円未満切り上げ**（Taker）。Maker のリベートは**円未満切り捨て**（小口では0円になりうる。保守側）
- レバレッジ: 2倍、**建玉管理料 0.04%/日を UTC 20時に持っている建玉にだけ1回**、証拠金維持率 **75% 割れで全建玉を強制決済**、空売りはレバレッジだけ
- 注文から約定までの**通信の遅れ**（既定 300ms）を置き、その時点の板で約定させる
- 配信が切れている・板が古い（5秒超）ときは**注文を受け付けない**（メンテナンスもここに含まれる）

### N-4 性能

- 板の更新は届くたびに状態を置き換えるだけ。描画は1秒に最大4回
- チャートは確定した足だけ保存し、描画は差分だけ

### N-5 保存

- 端末のブラウザの IndexedDB に置く。消えうる（ブラウザの掃除・プライベートモード）ので、書き出しを用意する
- 上限: 1分足と1分ごとの気配は銘柄ごとに7日、取引の記録は5,000件

### N-6 可用性

- 切れたら自動で再接続（1・2・4…最大30秒の間隔）。再接続したら購読し直す

## 5. 制約

- GitHub Pages は HTTP ヘッダーを付けられない → CSP は `<meta>` で指定。`frame-ancestors` は効かない（N-2 の埋め込み対策で補う）
- GMO の REST はブラウザから読めない（CORS の許可が無い）→ 過去の足・銘柄の仕様は配信で作るか同梱する
- GMO の配信の購読は1秒1回まで
- 端末を閉じている間は値を受け取れない

## 6. 構成の概要

```
[スマホのブラウザ]
  index.html（CSP）
   ├─ js/*.js（自前・ES モジュール）
   ├─ vendor/lightweight-charts（同梱・SRI）
   ├─ IndexedDB「toki-dojo-v1」（口座・注文・取引・1分足・気配）
   └─ WebSocket ──► wss://api.coin.z.com/ws/public/v1（ticker・orderbooks・trades）
[GitHub Pages]（静的ファイルを配るだけ・サーバーの処理なし）
```

## 7. 追加（2026-09-27）: 過去の足の中継

利用者の要望: 「開いたら常に1画面ぶんの足がほしい」。

- GMO の過去の足（`GET /public/v1/klines`）は公開だが、**ブラウザから読む許可（CORS）が無い**（2026-09-27 に実測）。そこで、読むことだけを取り次ぐ**中継**を Cloudflare Workers（無料枠）に置く
- 中継の役割は1つだけ: 決まった銘柄・足の長さ・日付の過去の足を GMO から取って、そのまま返す
- 要件
  - **N-1（分離）**: 中継は鍵を持たない・書き込みの道が無い・GET だけ。TOKI の Actions とは場所も IP も別。**中継が落ちても練習は止まらない**（今まで通り「開いてからの約定」で足を作る）
  - **N-2（安全）**: 許可した組み合わせ以外は断る（何でも取り次ぐ中継にしない）。読める元は `https://somanakahashi-ops.github.io` だけ。返ってきた値はアプリ側で検査する。無料枠（1日10万回）を使い切られても、中継が止まるだけで他に害は無い
  - **N-3（本物らしさ）**: 過去の足は**見るためだけ**。約定の判定はこれまでどおりリアルタイムの板と約定だけで行う
