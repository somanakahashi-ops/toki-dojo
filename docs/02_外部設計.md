# 02 外部設計 — TOKI 道場

基本設計（01）の機能 F-1〜F-7 と非機能 N-1〜N-6 を、利用者から見える形に落とす。

## 1. 画面

スマホ縦（幅360〜430px）を基準にし、幅900px 以上では左にチャート、右に板・注文を並べる。
画面は3つで、下のタブで切り替える: **取引**・**振り返り**・**設定**。

### 1.1 取引画面

| 区画 | 表示と操作 | 対応 |
|---|---|---|
| 上の帯 | 銘柄の選択（8銘柄）・**現物／レバ**の切り替え（その銘柄にレバが無ければ押せない）・最終価格・24時間の高安・**接続の状態**（つながっている／再接続中／切断中）・スプレッド（円と%） | F-1 F-2 N-6 |
| チャート | ローソク足。足の長さ（1分・5分・15分・1時間）のタブ、MA の表示の切り替え。閉じていた時間は空白。**「まだ足が少ない」ときはその旨を表示** | F-3 |
| 板／約定 | タブで切り替え（PC では両方）。板は売り10段・買い10段と量の横棒、中央にスプレッド。**板の値段を押すと注文の値段に入る**。約定は時刻・値段・量・買い/売り（色） | F-2 |
| 注文 | 買い／売り、種類（成行・指値・逆指値）、数量（**枚数**か**円**で入れる。円なら最小数量の刻みに切り下げて枚数を表示）、値段（指値・逆指値のとき）、**見込み**（約定の見込み値段・手数料・必要な現金か証拠金）。レバは「新規」、決済は建玉の行から行う。新規のレバには損切り・利確の値段を任意で付けられる | F-4 N-3 |
| 建玉・注文 | 現物の保有（数量・平均取得・評価損益・**売る**）、レバの建玉（向き・数量・建値・評価損益・**損切り／利確の変更**・**決済**）、待機中の注文（**取消**） | F-4 F-5 |
| 口座 | 資産の合計・現金・評価損益・証拠金維持率（レバがあるとき） | F-5 |

## 2. 利用の流れ

1. **初めて開く**: 仮想資金3万円の口座ができる。BTC・現物が選ばれ、配信につながり、板と約定が動き出す。チャートは空で「開いてからの約定で足を作ります」と出る
2. **注文〜約定**: 注文を押す → 見込みを確かめて確定 → **通信の遅れのぶん待って**、その時点の板で約定（成行）／待機に入る（指値・逆指値）→ 約定したら知らせる（画面の上に短く）
3. **待機中の注文**: 指値は約定の値段が指値を**突き抜けたら**、逆指値は線を**越えたら**動く。約定したら知らせる
4. **決済**: 建玉の行の「決済」→ 成行で決済 → 取引の記録に1件増える
5. **切断**: 帯が「再接続中」になり、**注文のボタンが押せなくなる**。つながったら購読し直す
6. **閉じていた・切れていた間**（30秒超の空白）: その間の値動きが分からないので、**待機中の注文は取り消し**、理由を知らせる。建玉は残す。建玉管理料は、空白の間に UTC 20時をまたいでいれば、またいだ回数ぶん引く。ロスカットは再開した時点の値で判定する
7. **強制決済（レバ）**: 維持率が75%を割ったら全建玉を成行で決済し、知らせる
8. **リセット**: 設定から資金を選び直す

## 3. 外部との取り決め

### 3.1 GMO の公開配信（WebSocket）

- 接続先: `wss://api.coin.z.com/ws/public/v1`（認証なし）
- 購読: `{"command":"subscribe","channel":"ticker"|"orderbooks"|"trades","symbol":"BTC"}`（レバは `BTC_JPY` など）。**購読と解除は1秒に1回まで**（超えると ERR-5003）→ 1.1秒おきに順番に送る
- 解除: `{"command":"unsubscribe", ...}`
- 受け取る電文（2026-09-27 に実測）:
  - ticker: `{channel, symbol, ask, bid, last, high, low, volume, timestamp}`（値は文字列の数値）
  - orderbooks: `{channel, symbol, asks:[{price,size}×最大30], bids:[...], timestamp}`（毎回まるごと）
  - trades: `{channel, symbol, price, side:"BUY"|"SELL", size, timestamp}`（side は成行で入った側）
- 購読する範囲: **表示中の銘柄**と、**待機中の注文・建玉がある銘柄**（見ていない銘柄の注文も判定するため）。同時に最大6銘柄
- 切断: 自動で再接続（1・2・4…最大30秒）

### 3.2 公開リポジトリ

- 中身: `index.html`・`css/`・`js/`・`vendor/`（チャート部品と使用許諾）・`docs/`（この設計）・`test/`
- 置かないもの: API キー・TOKI の戦略や状態・個人のデータ・自動で動くワークフロー
- 配信: GitHub Pages（main のルート）

## 4. 書き出しの形式

- CSV: 1行1取引。列 = 番号, 銘柄, 市場(現物/レバ), 向き, 数量, 建値, 決済値, 建てた時刻(JST), 決済した時刻(JST), 保有(分), 手数料, 建玉管理料, 損益, 決済の理由, メモ。**`= + - @` で始まるセルは先頭に `'` を付ける**
- JSON: `{version, exportedAt, account, trades, fills}`

## 5. 知らせる文言（主なもの）

| 場面 | 文言 |
|---|---|
| 最小数量未満 | 「数量が少なすぎます（最小 0.00001 BTC）」 |
| 刻みに合わない | 「数量は 0.00001 BTC 刻みです。0.00012 に直しました」（自動で切り下げて確かめてもらう） |
| 現金が足りない | 「現金が足りません（必要 3,012円・現金 2,500円）」 |
| 保有が足りない（現物の売り） | 「売れるのは保有している 0.0002 BTC までです」 |
| 証拠金が足りない | 「証拠金が足りません（必要 1,500円・余力 900円）」 |
| 配信が切れている・板が古い | 「値が届いていないため注文できません（再接続中）」 |
| 板が足りない | 「板の厚みが足りず、0.5 のうち 0.3 だけ約定しました」 |
| 空白で注文を取り消した | 「アプリが閉じていた間の値動きが分からないため、待機中の注文 2件を取り消しました」 |
| 強制決済 | 「証拠金維持率が75%を下回ったため、レバレッジの建玉をすべて決済しました」 |
