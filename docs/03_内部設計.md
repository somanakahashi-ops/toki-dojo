# 03 内部設計 — TOKI 道場

## 1. 部品と責務

ビルドはしない。`index.html` が `js/main.js` を ES モジュールとして読み、他はそこから import する。

| 部品 | 責務 | 依存 |
|---|---|---|
| `js/config.js` | 銘柄の仕様（GMO `/v1/symbols` の実値・取得日）、レバの規約、上限値。**定数だけ** | なし |
| `js/engine.js` | 約定の規約の**純粋な関数**（丸め・手数料・板を食う・突き抜け判定・逆指値の発火・維持率・建玉管理料の回数）。副作用なし・時刻も引数で受ける | config |
| `js/validate.js` | 受け取った電文の検査（JSON・型・有限・正・長さの上限）。**外から来たものは必ずここを通す** | config |
| `js/ws.js` | 接続・購読の順番待ち（1.1秒おき）・再接続・電文の振り分け・最後に受け取った時刻 | validate |
| `js/market.js` | 銘柄ごとの相場の状態（板・最良気配・最終約定・受け取った時刻）。**板が古いかの判定** | なし |
| `js/candles.js` | **購読中の全銘柄**について、約定から1分足を作り、5分・15分・1時間に束ねる。1分ごとの最良気配（偶然との比較の材料）も記録（04 R-1） | store |
| `js/account.js` | 口座・現物の保有・レバの建玉・注文の管理。注文の受付 → 遅れの後に engine で約定 → 口座に反映 → 取引の記録。待機中の注文の判定、損切り・利確、強制決済、建玉管理料、空白の扱い | engine, market, store, config |
| `js/review.js` | 集計と偶然との比較（**純粋な関数**＋記録の読み出し） | engine, config |
| `js/store.js` | IndexedDB の読み書き（すべて try/catch）。使えなければ記憶だけで動き、その旨を返す | なし |
| `js/ui/*.js` | 描画と入力。**`textContent` と `createElement` だけ**で組む | 上のすべて |
| `js/main.js` | 起動・埋め込みの検出・部品の結線・画面の見え隠れの扱い | すべて |

依存は上から下への一方向。`engine`・`review` の計算部分は DOM にも IndexedDB にも触らない（node でテストできる）。

### 1.1 追加（2026-09-27）: 過去の足

| 部品 | 責務 |
|---|---|
| `relay/worker.js` | 中継（Cloudflare Workers で動く。アプリには含まれない） |
| `js/history.js` | 中継から過去の足を取り、検査して返す。記憶に60秒だけ置く（端末には保存しない） |
| `js/candles.js` | 過去の足（足の長さごと）と、配信から作った1分足を重ねて返す |

流れ: 銘柄・足の長さが変わる／空白から戻る → `history.load(inst, frame)` → `candles.seed(inst, frame, bars)` → チャートを描き直す。
重ね方: 同じ時刻の足は、始値＝過去の足、高値・安値＝両方の広い方、終値＝配信（開いた分は途中から数え始めるため）。

## 2. データの形

数量・値段は数値（JS の double）で持ち、**数量は銘柄の刻み、値段は値段の刻み、円は整数円**に丸める境目を engine に集める。

```
Instrument = { key: "BTC" | "BTC_JPY", base: "BTC", market: "spot" | "lev" }

Order = {
  id, inst, market, side: "BUY"|"SELL",
  type: "MARKET"|"LIMIT"|"STOP",
  intent: "open"|"close",           // 現物の買い=open・売り=close、レバの新規=open・決済=close
  size, price?,                     // LIMIT の値段・STOP の発火の線
  positionId?,                      // レバの決済・損切り・利確の対象
  role?: "sl"|"tp",                 // 建玉に付いた損切り・利確
  status: "pending"|"working"|"filled"|"canceled"|"rejected",
  createdAt, executeAt, doneAt?, reason?
}

Fill = { id, orderId, inst, side, size, price, fee, liquidity: "taker"|"maker", time }

SpotHolding = { base, qty, cost }            // cost＝取得の総額（手数料込み）。平均取得＝cost/qty

LevPosition = {
  id, inst, side, size, entryPrice, entryNotional, openedAt,
  sl?, tp?                                   // 値段（無ければ未設定）
}

Account = { version, initialCash, cash, spot: {base: SpotHolding}, lev: [LevPosition],
            orders: [Order], reserved: {cash, spot: {base: qty}},   // 待機中の注文が押さえた分（04 R-5）
            lastCarryAt, lastSeenAt, createdAt }

Trade（決済1回＝1件）= {
  id, inst, market, side（建てた向き）, size, entryPrice, exitPrice,
  entryTime, exitTime, fees, carry, pnl, exitReason: "手動"|"損切り"|"利確"|"強制決済"|"指値"|"逆指値",
  memo, liquidity: {entry, exit}
}

Candle1m = { inst, t（分の始まり UTC ms）, o, h, l, c, v }
Quote1m  = { inst, t, bid, ask }            // その分の最後の最良気配
```

## 3. 状態の遷移

### 3.1 注文

```
受付(pending) ──遅れ(既定300ms)──► 判定
   判定: 成行 → 約定(filled) / 一部だけ約定して残りは取消 / 拒否(rejected: 値が古い等)
         指値で既に約定できる値段 → 約定できるぶんは Taker で約定、残りは待機(working)
         指値・逆指値 → 待機(working)
待機(working) ──約定が指値を突き抜けた──► 約定(filled: Maker・指値の値段)
待機(working) ──約定が線を越えた（逆指値）──► 遅れ → その時点の板で成行の約定
待機(working) ──利用者の取消／空白の検出／建玉の消滅──► 取消(canceled)
```

- 損切りと利確（role=sl/tp）は1組で、どちらかが約定したらもう一方を取り消す（OCO）
- 決済の注文は、対象の建玉が無くなったら取り消す

### 3.2 レバの建玉

```
新規の約定 → 保有 ──一部の決済──► 保有（数量が減る）
             保有 ──全部の決済／損切り／利確──► 決済（取引の記録）
             保有 ──維持率 < 75%──► 強制決済（全建玉を成行）
```

### 3.3 接続

```
未接続 → 接続中 → 購読中（電文が流れる）
                  └─ 切断 → 再接続待ち（1,2,4,…,30秒）→ 接続中
```

- 購読は順番待ちの列に積み、1.1秒おきに1つずつ送る
- 購読する銘柄の集合 = 表示中 ∪ 待機中の注文 ∪ 建玉（最大6）。変わったら差分だけ購読・解除する

## 4. 時刻の扱い

- 値に関わる時刻（約定・足・気配）は**配信の `timestamp`（サーバーの時刻）**を使う。端末の時計はずれうるため
- 「今」の基準は、最後に受け取った電文のサーバーの時刻 ＋ それからの経過（端末の時計の差分）
- 1分足の区切りは UTC の分の境目
- 建玉管理料は、**UTC 20:00 をまたぐたび**、その時点で持っている建玉の `entryNotional × 0.04%` を引く（円未満切り上げ）。空白の間にまたいだ回数も数える
- 空白: 表示中の銘柄の電文が30秒超途切れた、または画面が隠れていて戻ったとき

## 5. 保存（IndexedDB「toki-dojo-v1」）

| 置き場 | 鍵 | 中身 | 上限 |
|---|---|---|---|
| `kv` | 名前 | 口座（Account）・設定 | — |
| `trades` | id | 取引の記録 | 5,000件（古いものから消す） |
| `fills` | id | 約定 | 20,000件 |
| `candles` | `[inst, t]` | 1分足 | 銘柄ごとに7日 |
| `quotes` | `[inst, t]` | 1分ごとの最良気配 | 銘柄ごとに7日 |

- 口座は変わるたびに保存する（1秒に1回まで）。取引・約定はその場で追加する
- すべての読み書きを try/catch で包む。使えなければ `store.available=false` として画面に「このブラウザでは記録が残りません」を出す

## 6. 安全の仕組み

- **CSP**（`index.html` の `<meta>`）: `default-src 'none'; script-src 'self'; style-src 'self' 'sha256-3pRED1tOXas1FXFoPb9TGCjmYe9XQsmO9OV23khV2nY='; img-src 'self' data:; connect-src wss://api.coin.z.com https://toki-dojo-relay.soma-nakahashi.workers.dev; font-src 'self'; manifest-src 'self'; base-uri 'none'; form-action 'none'`
  - style-src のハッシュは、チャート部品が出す TradingView のロゴの `<style>`（中身は固定の文字列）だけを許す。`'unsafe-inline'` は使わない（04 R-13）
  - インラインのスクリプト・スタイルは書かない（style 属性も書かない。見た目の切り替えはクラスで）
- **描画**: `textContent`・`createElement`・`classList` だけ。`innerHTML`・`insertAdjacentHTML`・`eval`・`new Function` を使わない（構造のテストで固定）
- **電文の検査**（validate.js）
  - 大きさ 256KB 以下で JSON として読めること
  - 数値は有限・正（数量は 0 以上）
  - 板の段は 100 以下
  - 銘柄は購読しているものだけ
  - 外れたら捨てて数える
- **上限**: 約定の流れは表示30件・記憶200件、足・保存量は §5
- **埋め込みの検出**: `window.top !== window.self` なら描画をやめて、Pages の URL を直接開くよう案内する
- **書き出し**: CSV の数式の注入を防ぐ（`'` を前に付ける）
- **チャート部品**: `vendor/` に同梱し、`<script src="vendor/..." integrity="sha256-...">` で読む

## 7. 本物らしさの規約の置き場

| 規約 | 置き場 |
|---|---|
| 最小数量・刻み・値段の刻み・手数料 | `config.js`（`/v1/symbols` の実値） |
| 成行の約定（板を食う・足りなければ残りは約定させない） | `engine.sweep()` |
| 指値の突き抜け・逆指値の発火 | `engine.limitHit()`・`engine.stopHit()` |
| 手数料の切り上げ／リベートの切り捨て | `engine.feeYen()` |
| 維持率・強制決済 | `engine.marginRatio()`・`account` |
| 建玉管理料 | `engine.carryCount()`・`account` |
| 通信の遅れ | `account`（受付から executeAt まで待つ） |
| 値が古いときは注文しない | `market.isFresh()`（5秒） |
